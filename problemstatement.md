Theme 8: Multi-Agent AI Reasoning & Verification Engine Problem Statement: Develop a multi-agent AI reasoning platform in which specialized agents collaborate to solve complex tasks while every important output is independently verified before acceptance. The system should separate generation from verification and use evidence, structured checks, tool execution, and contradiction analysis to identify hallucinations, invalid reasoning, unsupported claims, incorrect API usage, unsafe actions, and low-confidence conclusions. When a failure is detected, the system should route the task back for correction, request additional evidence, or reject the task when reliable completion is impossible. The platform must remain dependable when information is incomplete, ambiguous, conflicting, or deliberately misleading. Key Functionalities: • Specialized Agent Orchestration: Coordinate planner, researcher, coder/tool-use, verifier, critic, and finalizer agents with explicit responsibilities. • Evidence Retrieval & Grounding: Retrieve relevant evidence and link claims to supporting sources or structured data. • Independent Verification: Use separate verification paths to test factual claims, calculations, code/API usage, and logical consistency. • Contradiction & Risk Detection: Detect conflicting evidence, unsupported claims, unsafe actions, and low-confidence conclusions. • Self-Correction Loop: Return failed outputs to appropriate agents, track revisions, and re-verify before acceptance. • Decision & Audit Layer: Expose evidence, confidence, agent decisions, verification results, and rejection reasons. Advanced Requirements: • Handle ambiguous tasks, incomplete data, conflicting sources, misleading documents, and invalid APIs. • Recognize when evidence is insufficient and explicitly decline unreliable conclusions. • Use sandboxed execution for code or tool verification where appropriate. • Measure verification quality separately from generation quality. Deliverables: • Working multi-agent AI orchestration prototype with clearly separated agent responsibilities. • Evidence retrieval/grounding module for supporting important claims. • Independent verification layer for factual, logical, computational, or tool-use outputs. • Contradiction, hallucination, unsupported-claim, and unsafe-action detection module. • Self-correction and re-verification workflow. • Decision/audit interface showing evidence, confidence, verification results, revisions, and rejection reasons. • Evaluation set covering ambiguous, incomplete, conflicting, and misleading inputs. • Source code, agent architecture/prompt documentation, evaluation metrics, and demonstration results. Mandatory Deployment & GitHub Requirements: • The complete application must be deployed and accessible through a working deployment URL. • The complete source code must be pushed to a public GitHub repository before final evaluation. • The GitHub repository must contain a README with project overview, architecture, setup instructions, deployment URL, and team/member details. • The deployed version must match the submitted GitHub source code and be functional during evaluation. • Teams must ensure that the deployed application can be demonstrated by the jury without requiring local setup. Presentation & Evaluation Requirement: Every team must be prepared to present and demonstrate their solution to the evaluators if requested. The team must be able to explain the problem approach, system architecture, key implementation decisions, working features, deployment, and results during evaluation.
